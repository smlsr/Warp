---
name: warp
description: Start or tick the Warp master loop
---

Run the `warp` skill. If the user said "start", keep passing while `orchestrator.py parent-exit` prints `parent: stay`. That is while the loop is running and the listener is supposed to be up, while any ticket is not merged or parked. Do not treat a launch refusal, or an empty ready list while agents are out, as idle. `parent: exit` is when every ticket is merged or parked, or the run is paused or stopped. Only then run `scripts/session_note.py --type session-stop`, which releases the listener. Pause and stop still sync state, and then the listener may stop. Re-read the beam every pass. Do not implement tickets in this command. Before the pass, run `scripts/resume_hint.py` and follow it. Each pass runs `orchestrator.py supervise` and `inbound.py apply-pending`, reads `.warp/tickets/<id>/`, patches the live beam, dispatches with `checkout.py launch` and one subagent per worktree, pushes the beam, and passes again. `.warp/config.yaml` is not committed. Plugin hooks do not run on cloud runners.

The listener is a Subagent of this parent turn. One for the beam, not one per ticket. It shares this session and this checkout. It is not a separate Agent. Start one subagent per ticket in its own worktree, in parallel up to maxAgents. It loops until pause, stop, or it returns `recycle`. Claim with one `--turn` id. `listener: started` and `listener: start` mean start that one Subagent. `listener: hold`, `listener: backoff`, `listener: cap`, and `listener: already running` mean do not start a second. `start <id>` is a new Shuttle. `resume <id>` continues that Shuttle: send the follow-up, do not start a second subagent. `shuttle: hold`, `spawn: cap`, and `spawn: closed` mean do not start one. `bugbot: request` is once per head commit. `bugbot: hold` means that commit was already requested. If `runState` is paused or stopped, or `parent-exit` prints `parent: exit`, do not spawn. The listener and each Shuttle exit. A running flag from the previous turn does not block this tick. When it returns, run `supervise --returned` and start one replacement straight away if the loop is still running.

Run `scripts/beam.py watchdog` on this tick, before `ready()`. It fetches each in-flight ticket directory (`.warp/tickets/<id>/`) and patches the live beam before it decides anyone died. It does not copy the branch beam. A fresh Shuttle heartbeat is left alone. `watchdog: skipped` means do not fetch and do not recover. `listener: subagent` means this tick starts one listener Subagent if claim says `started`. Do not start a separate Agent for it. `shuttle: replace <id>` means launch exactly one Shuttle for that same ticket and keep its branch. A second tick must not launch another Shuttle. `/warp-pause` and `/warp-stop` stop the listener. It must not keep reading while paused or stopped.

On every merge, the live beam goes onto main in that merge or in the commit pushed immediately after. The ticket branch's beam is not the one that lands. Close the window, open a new one, `/warp-start`: state comes from main plus ticket folders.
