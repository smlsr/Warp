---
name: warp
description: Start or tick the Warp master loop
---

Run the `warp` skill. You are the parent. You are the only agent that starts another agent, and the only agent that waits. Every Shuttle and every listener poll does one step and returns one line. `docs/LIFECYCLE.md` is the rule.

If the user said "start", run passes in this turn while `orchestrator.py parent-exit --beam .warp/beam.json --wait --session <session>` prints `parent: stay`. `<session>` is the id `scan.py start` printed as `parent: session <id>`. That command is the one wait in a run: it blocks until a ticket folder changes, the listener is due, the run halts, or `pollSeconds` pass. Do not sleep, set a timer, or subscribe to anything else. Do not treat a launch refusal, or an empty ready list while agents are out, as idle. `parent: exit` is when every ticket is merged or parked, or the run is paused or stopped. Then run `scripts/session_note.py --type session-stop`, start nothing, and end the turn. `parent: exit superseded` means a later `/warp-start` or `/warp-resume` owns the run: end the turn at once. `pass: aborted` from `supervise` means a pause or a stop landed during the pass: start nothing from that output. Re-read the beam every pass. Do not implement tickets in this command. Before the first pass, run `scripts/resume_hint.py` and follow it. Each pass runs `inbound.py apply-pending` and `orchestrator.py supervise`, reads `.warp/tickets/<id>/`, patches the live beam, dispatches with `checkout.py launch` and one subagent per worktree, pushes the beam, and waits with `parent-exit --wait`. `.warp/config.yaml` is not committed. Plugin hooks do not run on cloud runners. Every check here is a script you run.

The listener is a Subagent of this parent turn, and it is one poll. One listener for the beam, not one per ticket. It shares this session and this checkout. It is not a separate Agent. `listener: poll` from `supervise` is followed by the prompt for it: start exactly one `warp-listen` Subagent in the foreground with those lines, wait for `listen: <count>`, then run `inbound.py apply-pending`. It does not loop and it does not sleep. `listener: hold`, `listener: idle`, and `listener: none` mean do not start one. Start one subagent per ticket in its own worktree, in parallel up to maxAgents. `start <id>` is a new Shuttle: run `checkout.py launch --id <id>` and pass the subagent only the lines below `prompt: pass every line below this one to the subagent, and nothing above it`. `resume <id>` continues that Shuttle: send the follow-up, do not start a second subagent. `shuttle: hold`, `spawn: cap`, and `spawn: closed` mean do not start one. `checkout.py launch` prints no prompt while the run is paused, stopped, or finished. `bugbot: request` is once per head commit. `bugbot: hold` means that commit was already requested. If `runState` is paused or stopped, or `parent-exit` prints `parent: exit`, do not spawn. Each Shuttle reads `reap: exit` at its next check and returns.

Run `scripts/beam.py watchdog` on this tick, before `ready()`. It fetches each in-flight ticket directory (`.warp/tickets/<id>/`) and patches the live beam before it decides anyone died. It does not copy the branch beam. A fresh Shuttle heartbeat is left alone. `watchdog: skipped` means do not fetch and do not recover. The watchdog prints no listener line. `shuttle: replace <id>` means launch exactly one Shuttle for that same ticket and keep its branch. A second tick must not launch another Shuttle. `/warp-pause` and `/warp-stop` end every agent in `.warp/agents.json` and, with `CURSOR_API_KEY`, cancel and archive this run's cloud agents. The listener must not keep reading while paused or stopped.

On every merge, the live beam goes onto main in that merge or in the commit pushed immediately after. The ticket branch's beam is not the one that lands. Close the window, open a new one, `/warp-start`: state comes from main plus ticket folders.
